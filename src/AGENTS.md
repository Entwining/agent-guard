# Rust implementation

- During App Data traversal, stop at lexically protected paths before each probe and use readlink alone; inode and stat checks belong only to SSH identity. Shell patterns and API globs have separate syntax owners; API matching must not narrow Bash/POSIX protected-path coverage.
- Evaluation cost is part of correctness: work must stay polynomial in statements, words and loop depth. Keep an unknown value as one unknown word instead of enumerating alternatives, and merge states that share a resource identity before they branch again. Branch, loop and alternative-environment snapshots share unchanged state (deltas or `Rc`) instead of cloning owned maps and vectors, because those clones copy entries rather than share the existing storage. Evaluate a command-substitution body once rather than once per combination of loop candidates or cwd alternatives. A merge must not erase a difference in protection or role. Protect a cost fix with a `cfg(test)` operation counter whose growth across input sizes is asserted; wall-clock assertions in debug tests flake without detecting growth, so latency is measured on release builds outside unit tests.
- Each limit in `limits.rs` bounds the one quantity it names: `MAX_NESTING` is syntactic and recursive depth, not list position. Reaching a limit fails closed with its existing error kind. When a benign input reaches one, check whether the limit counts the wrong quantity or the representation multiplies; do not raise or lower the limit to change that input's verdict.
- A convention applies only to programs that define it, such as `@FILE`; a generic default must not widen a role across programs. Model an unknown or unmodelled case as its own state rather than reusing a neighbouring one.
- Evaluation state, including caches and counters, belongs to the evaluation and travels through arguments and return values; do not add process-global mutable state. Use ordered collections wherever iteration order can reach a reason, record or fixture.
- Fix a lint by changing the code; do not add `#[allow]` to make a build pass.
- Unsafe code stays forbidden. Lifting it needs FFI or a measured hot path that safe code cannot reach, confined to one module with a `SAFETY` comment for each block.
- `brush-parser`, `tree-sitter` and `tree-sitter-bash` are exact pins because parser output is policy semantics. An upgrade is a behavior change: run the contract, differential and parser-comparison tests and account for every verdict change.
- Tests do not take scratch space or helper binaries from the invoker's environment, such as `CARGO_TARGET_DIR`, so they pass under `cargo test`, `make rust-check` and `cargo mutants` alike. A test that touches disk or runs a helper binary is an integration test using `env!("CARGO_TARGET_TMPDIR")` and `env!("CARGO_BIN_EXE_<name>")`; Cargo sets neither for unit tests or examples. Name a new test after the behavior it protects and keep it with that behavior's owner.
