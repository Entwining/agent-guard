# v0.8.10

A search glob that matches any name is now refused over a directory reached through a link when a credential store's hidden directory lies below it, such as `rg -g '*' token ~/dots` when `~/dots` and `~/.claude` both link into one dotfiles repository; 0.8.9 refused the search only when it spelled the repository's own path. ripgrep enters every hidden name such a glob matches, while a glob that bounds names, such as `rg -g '*.lua' token ~/dots`, stays permitted.

A search that `xargs` runs walks the names `xargs` appends rather than its working directory, because macOS `xargs` does not run it on empty input, so `find .claude -type f -name '*.jsonl' | xargs rg foo` from the home directory is no longer refused as a broad scan. Under `-I` or `-J` without the marker in the command, the search still scans its working directory.

The `credential_store` refusal now says that the command reads a directory holding a client's credential store and first suggests naming the subdirectory or file needed, which also applies to `cp -R` and `tar`.
