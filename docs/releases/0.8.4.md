# v0.8.4

Every blocking reason now starts with a reason marker, `[<class>:agent-guard/<id>]`. The class is `policy`, `coverage` or `error`, and the ID names the checked condition. The marker comes first on Claude Code, Codex and Pi, so session logs and indexes can attribute a block without matching its wording. On Claude Code the marker comes before the `DENIED:` prefix, so a tool that expects a Claude Code hook reason to begin with `DENIED:` must now read the marker first. [Reason markers](https://github.com/Entwining/agent-guard/blob/v0.8.4/docs/setup.md#reason-markers) lists every ID with its stability rules: an ID survives rewording, and a retired ID is never reused.

A malformed event, a filesystem probe fault or the checker's deadline now blocks with its own reason and recovery instead of the generic `could not complete its check (guard failed)` sentence. A malformed event asks the checker owner to update the guard for the runtime's hook event. A hook registered with an unsupported command line blocks with a `usage` reason that names the supported form.

If you use Pi with the extension from the setup guide, copy the [updated example](https://github.com/Entwining/agent-guard/blob/v0.8.4/docs/setup.md#register-pi). When the guard gives no reason, for example because it could not start or ran out of time, the example's own reason now carries the `guard_unavailable` marker and names the failure.
