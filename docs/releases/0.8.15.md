# v0.8.15

A credential variable piped into a client's standard input, which v0.8.14 permits, is refused again where the value can reach the agent's output: when `script` runs the client, as in `printf '%s\n' "$DEPLOY_KEY" | script -q /dev/null ssh-add -`, because `script` hands its input to the client through a terminal that echoes it, and when the producer's standard output is redirected with `1<>`. Pipe the value straight into the client instead, as in `printf '%s\n' "$DEPLOY_KEY" | ssh-add -`. Every rule now reads a command run by `script` as reading a terminal rather than the pipe, so `echo hi | script -q /dev/null rg foo` is checked as a search of its directory.

curl reads a file only from an `@` at the start of a data or header value, or after the name in `--data-urlencode`, `--url-query` and `--variable`. So `curl -H 'From: me@.env'` is no longer denied as uploading `.env`, and a literal `@-` inside such a value no longer counts as sending standard input. A redirection of a descriptor other than standard output, such as `3>trace.log`, no longer stops a credential pipe from reaching its client.

`gh auth token --help` is permitted, as `mk get --help` already is.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.15/docs/setup.md#known-limits) list what the guard does not check on a credential pipe.
