# v0.8.5

Launchers that load an environment file are no longer refused for it. `uv run --env-file .env python app.py`, `op run --env-file .env -- npm start`, `dotenv -e .env -- node index.js` and the `uvx`, `npm exec`, `npx`, `pnpm exec`, `pnpm dlx` and `bunx` equivalents load the file themselves, so they are permitted. The command a launcher runs is now checked as its own program, so shell code it runs, as in `npx -- sh -c 'cat .env'`, is refused, and a script `uv run` executes with Python is read like any interpreter's script. `uv --directory`, `pnpm -C` and `env -C` move the inner command into their directory while redirections stay in the shell's, so `env -C` into an App Data directory is now refused. A launcher spelled with an option the guard does not know still treats every operand as read.

Cargo, `diskutil`, `tmutil` and `dscl` are read by subcommand. `cargo install --root ~/.cargo ripgrep`, `diskutil info /` and `tmutil listlocalsnapshots /` are permitted, while `cargo run` operands, arguments after `--` and other tools' subcommands keep their read checks. `node --env-file .env server.js` and `tsx --env-file .env` are permitted in the two-word form as well as with `=`.

Git pathspec magic is checked for the path it names, so `git diff HEAD -- ':(top).env'` and `git grep KEY -- ':(icase).env'` are refused. The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.5/docs/setup.md#what-a-command-does-when-it-runs) list the launcher, cargo and pathspec spellings the guard does not follow.

If you use Claude Code, update your hook entry from the [setup guide](https://github.com/Entwining/agent-guard/blob/v0.8.5/docs/setup.md#register-claude-code). It now sets `"onFailure": "block"`, which requires Claude Code 2.1.295 or later and blocks a call when the guard cannot start, times out or exits unexpectedly, instead of letting it run unchecked.
