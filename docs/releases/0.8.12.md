# v0.8.12

Arguments that `rex` and `sessidx` take as names are no longer refused as file reads, so `rex api describe client.key`, `rex do client.key` and `sessidx grep client.key` are permitted. A `rex do` script path, the transcript `sessidx show` opens, `--db`, `--root` and the other arguments of both programs are still checked as reads, and every argument of a program the guard does not know is still checked as a path.

Shell command lines and `diff` options are read with the program's own grammar as well: `bash -- -c 'cat .env'` runs a script named `-c` and is permitted, and `diff -r -x .env a b` takes `.env` as an exclusion pattern.

A word is treated as a name only where the command line settles what it is. Where it does not, the guard now assumes the word may name a file, so some commands that 0.8.11 permitted are refused:

- The value of an option that a known program does not define is read as a path, as in `cat --include .env input.txt`.
- A word the shell sets at run time where an option could stand may select that option, so the arguments after it are read: `bash "${MODE:--x}" 'cat .env'` and `curl "${V:---url}" client.key` are refused. A short option whose value the shell sets stays open the same way, so `rg -g*.rs .key .` and `rg -g"$G" .key .` are refused, while `rg -g'*.rs' .key .` and `rg --glob="$G" .key .` keep `.key` a pattern.
- A variable the command has not assigned may hold a value the shell inherited, so `cat "${FOO+.env}"` is refused.

To keep such a command permitted, quote glob patterns, spell options literally rather than through variables, and assign or `unset` a variable before reading it.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.12/docs/setup.md#known-limits) now include the cases this reading leaves to operating system read restrictions.
