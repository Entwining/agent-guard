# v0.8.17

Environment templates named after the file they seed can now be read. v0.8.16 refused every `.env.` name except `.env.example` and `.env.age`, so an agent could not read, diff or copy `.env.local.example`, `.env.production.example` or another template that a project commits and its setup script copies into place. A name now counts as a template when it starts with `.env.` and its last dot-separated segment is `example`, in any case: `cat .env.local.example`, `git diff -- .env.local.example` and `cp .env.local.example .env.local` are allowed.

Names that only resemble a template stay refused: `.env.example.local`, where `example` is not the last segment, `.env.sample`, `.env.template`, and patterns such as `.env.*` that can select a real environment file. Credential files whose names end in `.example`, such as `~/.aws/credentials.example`, are still refused.

Because a template name is no longer protected, `mv .env.local .env.local.example` is now refused for moving an environment file's contents to a readable name, as `mv .env.local .env.example` already was.
