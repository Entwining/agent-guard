## Command decisions

- Directory changes are no longer treated as file reads. Entering a directory and printing a literal is allowed; reads and scans that follow are checked in the directory where they run.
- Physical `cd -P`, `env -C` and fd base directory changes retain link traversal before `..`. Logical `cd -L` keeps logical traversal. Chained commands, functions, compound commands and substitutions preserve the relevant success and failure directories without carrying a failed branch into a successful absolute escape.
- Docker `--` and `--entrypoint` values, Git namespace and executable path names, and SSH transport operands no longer become unintended file reads. Node's `--env-file-if-exists` has the same client use role as `--env-file`.
- Inline environment dump detection recognizes dump commands rather than matching an incidental word inside an expression.

## Hook reliability

The shell entry establishes the runner's process group before Bun starts and owns its three second deadline and cleanup. A failed or stalled runner cannot leave ordinary descendants holding the hook pipes. Complete output is forwarded, and operational failures still deny the call.

Unresolved operand and file redirect suffixes are judged without passing them to dereferencing helpers. Fixed prefixes still reveal protected aliases, and case variants of SSH paths retain the same lexical decision. Determined public SSH files keep their identity checks.

## Maintenance and verification

Source directories now follow shell parsing, target inference, filesystem checks and policy ownership. The curl, tar and wget adapters have separate modules; curl option letters remain shared with trace detection. Harness drivers and typed fixtures have descriptive names, and runtime and experiment results are written outside the checkout. Incomplete runtime observations remain unverified in reports.

The release passed lint, formatting, type checks, 1328 tests, three process verification rounds and independent adversarial reviews. Known limits and the verified distinction between hook coverage and macOS policy belong to [the setup guide](https://github.com/LoopHubs/agent-guard/blob/v0.5.0/docs/setup.md#safety-model-and-limits).
