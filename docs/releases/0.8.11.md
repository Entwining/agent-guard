# v0.8.11

Patterns that select the files inside a credential directory are now refused, such as `cat ~/.gnupg/*/*` and `cat ~/.gnupg/priv*/*`, which expand to GnuPG's private keys. A pattern with fixed text in its file name, such as `cat ~/.gnupg/*/*.json`, is still compared by name.

A credential directory named with quotes or through the working directory is now recognized as it is when spelled plainly: `cd x/.config/glab-cli && cat *` and `cat 'x/Library/Application Support/glab-cli'/*` are refused, as `cat x/.config/glab-cli/*` already was.

Literal paths are matched against the same credential list as patterns. `config.yml` in a project's own `glab-cli` directory is no longer refused, while `.config/glab-cli/config.yml` and `Application Support/glab-cli/config.yml` stay protected anywhere. A path below a credential name stays protected when it is read through `find` or `fd` items, search filters or an unresolved prefix, as in `fd . x/private-keys-v1.d/keys/part -x cat`. A relocated glab directory that neither `XDG_CONFIG_HOME` nor `GLAB_CONFIG_DIR` in the hook's environment names is protected only by the names that identify its credential file, as gh's already was.

Claude Code denials no longer end with "Do NOT bypass this restriction or retry the same blocked command."; each reason still names a safe alternative.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.11/docs/setup.md#known-limits) now describe two cases the guard leaves to operating system read restrictions: Claude Code's shell runs `grep` as an embedded ugrep that reads the files inside a directory operand, hidden ones included, so `grep TOKEN .` can read an untracked `.env`; and below an unresolved prefix, a store file that only its place in HOME identifies, such as `cat "$d/.dbt/profiles.yml"`, is not protected.
