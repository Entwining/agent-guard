# v0.8.13

Option values are now read with each program's own option grammar, so their role no longer depends on how the option is spelled. A glued, grouped or `--name=VALUE` value that names an input file is checked as a read, so `sed -f.env`, `awk -f.env`, `xargs -a.env`, `du --files0-from=.env`, `git archive --add-file=.env`, `tree --fromfile .env` and `sudo -uroot cat .env` are refused. A value that writes to or enters App Data is refused the same way, as in `sort -o<App Data>`, `git diff --output=<App Data>`, `fd -C<App Data>` and `uv run -p<App Data>`.

Values that a program writes or takes as data are no longer refused as reads. `sort -o .env`, `git diff --output .env`, `git archive -o .env`, `rsync --log-file .env` and `openssl dgst -out .env` write their file, and `awk -F .env`, `rsync --out-format=.env`, `cp --suffix .env` and `diff --label .env` take `.env` as text. `cat @.env` reads a file literally named `@.env`, while a program the guard does not know may still read either name.

Maskey's `mk run` is now a launcher whose command is checked as its own program, so `mk run example/API_KEY -- printenv` is refused like `printenv`. The operands before its `--` name Maskey entries rather than files. `mk get` is refused because it prints the stored value, and `mk get --help` stays permitted. An `envchain` call with an option is now checked as an unknown program, and `envchain --list --show-value` is refused.

A value that passes through a copy, an export, a function argument, a quoted `"$*"` or a trimming pattern before a colon test keeps its refusal again, so `X="${FOO-.env}"; Y="$X"; cat "${Y:-public}"` is refused as it was before 0.8.12. `X="${FOO:-.env}"; cat "${X:0:1}"` is now refused as well, although it cannot read `.env`.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.13/docs/setup.md#known-limits) add that options stop where macOS stops them, so where a GNU tool that keeps reading options after an operand comes first in `PATH`, as in `du . --files0-from=.env`, the later option's file is not checked.
