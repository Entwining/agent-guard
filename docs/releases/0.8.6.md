# v0.8.6

Recursive searches narrowed by file-name filters are no longer refused. `grep -rn --include='*.ts' foo .`, `rg --hidden -g '*.rs' foo .`, `find src -name '*.rs' -exec grep -n foo {} +` and `find src -name '*.ts' | xargs grep -l foo` read only the files their filters name, so they are permitted. A filter that can select a credential or environment file anywhere below the search root, such as `--include='*.json'`, `--include='*.toml'` or `-name '.env*.local'`, is still refused, and so is a walk whose filters match every name, take their value from a shell variable, or come after `find`'s action. Names a `find` prints through `-exec` or `-printf` are not treated as bounded. A consumer that walks the names it is handed walks below each one, so `find . -name '*.mjs' | xargs rg foo` is permitted while `xargs grep -r` over the same names is refused.

The refusal for a hidden recursive search now names the forms that pass: `rg` without `--hidden` on a project path, naming any hidden project directory it needs, such as `rg PATTERN src .github`; `grep -r` or `find` restricted to source file names; or a search of named files without recursive flags. [How the guard decides](https://github.com/Entwining/agent-guard/blob/v0.8.6/docs/setup.md#how-the-guard-decides) describes the rule, and the [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.6/docs/setup.md#what-a-command-does-when-it-runs) list the spellings a narrowed walk can still read, such as a variant only a wildcard selects (`auth.json.bak` under `--include='*.bak'`) or names a command between `find` and `xargs` rewrites.
