# v0.7.0 (draft)

The source package now builds the Rust native runner behind the existing shell entry. The hook path and Claude Code, Codex and Pi registration formats remain unchanged. Development and acceptance tools also build with Rust.

Compared with v0.6.0, shell analysis follows more wrapper, binding, function, loop and pipeline forms, including recognized process-substitution producers. Command roles distinguish metadata, listing, reading, writing and client credential use. Unmodelled shell state is refused conservatively, and protected-path checks precede filesystem identity probes.

The native checker now explains refusals for events exceeding 262,144 serialized bytes, more than 64 nested shell delimiters, relative working directories and invalid UTF-8. Checker and runner deadlines remain below the shell entry's three-second bound; operational failures block the call. The setup guide records static-analysis and runtime coverage limits, including shell features the checker deliberately does not evaluate, such as `CDPATH`, zsh `hash -d` directories and `GIT_DIR` redirection; operating system read restrictions cover those reads.

Before publication, the Homebrew tap formula must switch its build dependency and command from Go to Rust. After the tagged release and tap update are accepted, existing users can run `brew update` and `brew upgrade loophubs/tap/agent-guard`, then verify the installed version, protocol and runtime hook loading. This draft does not change `VERSION`, publish a release, replace an installed hook or change client configuration.
