# v0.7.0

The source package now builds the Rust native runner behind the existing shell entry. The hook path and Claude Code, Codex and Pi registration formats remain unchanged. Development and acceptance tools also build with Rust.

Compared with v0.6.0, shell analysis follows more wrapper, binding, function, loop and pipeline forms, including recognized process-substitution producers. Command roles distinguish metadata, listing, reading, writing and client credential use. Unmodelled shell state is refused conservatively, and protected-path checks precede filesystem identity probes.

The native checker now explains refusals for events exceeding 262,144 serialized bytes, more than 64 nested shell delimiters, relative working directories and invalid UTF-8. Checker and runner deadlines remain below the shell entry's three-second bound; operational failures block the call. Some long loops and pipelines that v0.6.0 allowed now exceed the inspection budget and are refused with advice to split them: 29 of 73,446 calls in a replay of real agent sessions, a count that does not bound all possible inputs. The setup guide records static-analysis and runtime coverage limits, including shell features the checker deliberately does not evaluate, such as `CDPATH`, zsh `hash -d` directories and `GIT_DIR` redirection; operating system read restrictions cover those reads.

The formula now lives in `entwining/tap`, and Homebrew builds it with Rust instead of Go. Homebrew clears the formula's trust when it follows the redirect from `loophubs/tap`, so existing users must follow the [Homebrew upgrade steps](../setup.md#upgrade), which trust `entwining/tap/agent-guard` again before upgrading. Then verify the installed version, protocol and runtime hook loading. Registered hooks keep the `/opt/homebrew/bin/agent-guard` path.
