# v0.8.16

Commands that Rex starts in a terminal are now checked. v0.8.15 let any command after `--` in `rex run`, `rex split`, `rex new` and `rex window new` pass, so `rex run -- sh -c 'cat .env'` was allowed; that command is now checked as its own program, in the directory `-c` names. The `-c` directory is entered rather than read, so the usual `rex run -c "$HOME" -- …` and `rex new work -c "$HOME"` are no longer refused as a broad scan of the home directory. Text that `rex send` types into a terminal is still not checked.

Printing a credential variable is refused only where the value can reach the output:

- A variable whose name has no uppercase letter, such as a loop's `key` or a script's `token_id`, is the script's own variable, not a credential.
- Checking whether a credential is set or how long it is, with `${#API_TOKEN}` or `${API_TOKEN:+set}`, is allowed.
- Output of `echo`, `printf` or `printenv` sent only to `/dev/null`, as in `printenv API_TOKEN >/dev/null && echo set`, is allowed.
- A credential that `echo` or `printf` does not print, such as one in a prefix assignment like `TOKEN="$API_TOKEN" echo ok`, no longer refuses the command.

Any other expansion of the value is still refused, and so is output that zsh also writes elsewhere, as with `>&2 >/dev/null`, `>/dev/null | cat` or `1</dev/null`.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.16/docs/setup.md#known-limits) list what these rules leave out, such as a credential copied into a lowercase variable before it is printed.
