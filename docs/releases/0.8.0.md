# v0.8.0

Output filters are no longer read as file names. `gh api licenses -q '.[].key'`, `gh pr list --json title --jq '.[].pem'`, `gh api user --template '{{.login}}.key'`, `aws s3api list-objects-v2 --query 'Contents[].Key'` and jq filters that follow options, such as `jq --arg name x '.[].key' data.json`, were refused as credential-file reads and are now permitted. gh treats `-q`/`--jq` and `-t`/`--template` values as data only in `gh api` and the commands that take `--json`; files named by `gh pr create --template`, `gh api -F key=@file` and other operands are still checked.

Some calls that v0.7.0 permitted are now refused: jq with `-f` inside an option group, such as `jq -rf FILE`, an unquoted filter containing `*`, `?`, `[` or braces, such as `jq .[0].key data.json`, and a filter forwarded through `"$@"` or an array. After an unquoted expansion whose argument count the check cannot establish, the remaining arguments are checked as paths. Quote the filter or pass it directly; the setup guide lists these limits.

Homebrew bottles now include the third-party license notices in `LICENSE-THIRD-PARTY.md`.
