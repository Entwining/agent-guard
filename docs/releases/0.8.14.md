# v0.8.14

A credential variable printed by `echo`, `printf` or `printenv` is now permitted when its standard output is piped straight into a client that reads its standard input as a credential, so `printf '%s\n' "$DEPLOY_KEY" | ssh-add -`, `printf 'Authorization: Bearer %s\n' "$API_TOKEN" | curl -H @- https://api.example.com`, `printenv GH_TOKEN | gh auth login --with-token`, `printf '%s' "$REGISTRY_PASSWORD" | docker login -u ci --password-stdin registry.example.com` and `printf '%s' "$NEW_API_KEY" | mk set --stdin example/API_KEY` pass. curl counts as such a client when it sends standard input as a header, data, a form field or an upload (`-H @-`, `-d @-`, `--json @-`, `-F 'name=<-'`, `-T -`) and no other option reads it. Unlike the here-string `ssh-add - <<<"$DEPLOY_KEY"`, which macOS shells back with a temporary file, the pipe keeps the key off disk.

Every other next stage keeps the refusal, including `cat` or a compound command before the client, `xargs`, a variable that may name another program, and curl also reading standard input through `-K -`, `--variable`, `-w @-`, `--url @-` or `-b -`. So do zsh's `print`, here-string readers such as `tee`, and a producer whose output is redirected.

The [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.14/docs/setup.md#known-limits) list what the guard does not check on such a pipe, such as shell tracing with `set -x`, an external `/usr/bin/printf`, and curl's `--libcurl`.
