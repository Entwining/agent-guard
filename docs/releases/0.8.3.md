# v0.8.3

Grep and `rg` globs that name a generic file without its credential directory are no longer refused. Under a project root, `packages/*/config.json`, `**/config.json` or `credentials` reach only what the same search without a glob reaches, so they are permitted. A pattern still counts as a credential read when it spells the directory, or starts a component with a dot where the directory is hidden, such as `.config/*/config.yml`, `.*/*/config.yml` or `.aws/**/credentials`. Searches rooted at or above the home directory are still refused. For `rg`, a file one glob selects is now checked inside each hidden directory another glob enters, so `rg -g .config -g hosts.yml .` is refused, while `rg -g '*.ts' -g credentials .` is permitted.

gh's `hosts.yml` and glab's `config.yml` are protected in the directories `GH_CONFIG_DIR`, `GLAB_CONFIG_DIR` and `XDG_CONFIG_HOME` name in the hook's environment, following each client's precedence. Literal paths, wildcards, variable references and searches that reach those files are refused. The hook sees only the environment its consumer was started with, so the [known limits](https://github.com/Entwining/agent-guard/blob/v0.8.3/docs/setup.md#known-limits) recommend adding a relocated config directory to the consumer's own read restrictions.

`case` words and `[[ ]]` string and pattern operands are compared as text, so `case "$x" in ~/*)` and `[[ $x == ~/* ]]` are no longer refused as home-directory scans. Command substitutions inside them are still checked, and file tests such as `[[ -r ~/* ]]` keep their path checks.
